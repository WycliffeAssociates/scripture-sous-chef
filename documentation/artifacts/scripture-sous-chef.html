Read first

Five truths that keep the model straight

Most implementation details are consequences of these contracts.

01 / OWNER

Galley owns the world

Complete corpora, config, identity, cache and lifecycle stay resident. The caller never ships a prior or a changed set.

02 / MUTATE

Updates do not analyze

Mutation methods validate, hash, splice and mark dirty. The caller decides when to debounce and recompute.

03 / SNAPSHOT

No echo semantics

A one-chapter update may narrow work, but the next answer still contains findings for the complete resident corpus.

04 / EVIDENCE

Rules never read rules

Shared knowledge is a typed observation substrate. Consumers judge that evidence; they do not depend on another rule’s verdict.

05 / RECEIVER

The wire is wholesale

Wasm sends one packed snapshot. JS reconciles identities and object reuse; there is no engine diff or tombstone stream.

03
Inputs + identity

The caller’s order is the address space

Corpus validates ordered parallel arrays, derives contiguous book/chapter layout, and owns the hashes that prove cache validity.

0GEN 1:1
1GEN 1:2
2GEN 2:1

texts[] · analyzed verse text
0In the beginning…
1Now the earth…
2Thus the heavens…
3The book of…

Layout is owned proof

Book and chapter ranges are derived once, kept in caller order, and updated atomically by every mutation path. Chapter and folded book hashes make unchanged content reusable.

Identity is available early

expectedAnalysisId(), expectedTargetContextId() and hasReference() need no analysis. They fold owned hashes, config and an engine stamp.

Address versus display
Rust findings carry a global KeyIdx into this exact ordered corpus. The JS decoder resolves it through the retained keys[] snapshot and exposes sid; rebasing the internal index does not churn public identity.
04
Resident lifecycle

Mutation and publication are separate clocks

Dirty
Never analyzed, or resident inputs are ahead of the last successful publication.
analyze succeeds⇄changed mutation
CleanPublished
The latest successful findings describe exactly the current resident inputs.

Mutations coalesce

Several updateChapter/updateBook/updateConfig calls can remain Dirty until one analyze. A proven no-op preserves the current state exactly.

Failures commit nothing semantic

An injected map/reduce/judge/pack fault leaves Dirty, retains valid warmed work, and preserves prior partitions/publication. Retry without mutation reaches the cold result.

Persisted-first UI
A validated packed snapshot may render immediately while the resident engine cold-warms. Detailed lazy args remain unavailable until this Galley successfully publishes the matching analysisId.
05
The analyze call

One transition, two analysis lanes

The same transition serves cold one-shot and resident calls. Cache state narrows work; it never changes the answer.

Route

Close the enabled direct-rule set and ActiveSubstrates from final config.

Validate

Compare chapter content, schema, extraction config and reference stamps.

Map

Build dirty direct chapter records and dirty typed observations.

Reduce

Replay each affected book in order until boundary state converges.

Judge

Read complete corpus aggregates and judging knobs; compute outcomes.

Partition

Patch chapter-local records; retain untouched published partitions.

Assemble

Rebase to global KeyIdx and stable-sort by address, span and code.

Publish

Pack one complete buffer, then let JS decode and reconcile it.

Lane A

Direct per-verse rules

chapter stamp→scalar tape once / verse→u32 bit gates→chapter records

Rules that need only one verse share a classified scalar tape. Their cached product is chapter-local, so replacing one chapter leaves other addresses valid.

Lane B

Typed observation substrates

map chapter→reduce book→corpus aggregate→judge

Corpus-relative rules retain typed evidence and boundary carry. Twelve substrates serve the corpus-aware rules; casing has two consumer rules.

06
Map / reduce / judge

A substrate is evidence, not a rule

Its types make the incremental contract explicit and prevent one rule from covertly depending on another.

Observation

Chapter-local, predecessor-free extracted facts.

Boundary

All discourse carry entering/leaving a chapter.

ChapterReduced

Observation interpreted under entering state.

BookContribution

Canonical fold of ordered reduced chapters.

CorpusStats

Complete evidence across resident books.

Outcome

Judge-time decision for a typed evidence key.

Map is chapter-local

map_chapter sees one chapter and extraction-only config. It never sees a predecessor boundary or a judging knob, so moving an unchanged chapter preserves its observation.

Reduce owns seams

reduce_chapter walks left-to-right inside a book. If carry changes, cached observations replay until leaving state converges—unchanged text need not be rescanned.

Judge is read-only

Judging reads the complete aggregate and current knobs. It cannot mutate counting, which is why a sensitivity change can reuse mapped evidence.

Delta is explicit

Counts do not prove site equality. Substrates report the changed evidence/site channel needed to patch resident finding partitions safely.

Chapter boundary doctrine
A chapter boundary is not a discourse reset. Bracket stacks, casing position and punctuation seams travel in typed Boundary state; replay is sequential and deterministic inside a book.
07
Resident state

AnalysisCache has three homes

Each section invalidates for different reasons. The fourth card is intentionally outside the cache.

PrepSection

Content-keyed direct per-chapter findings, plus its configuration fingerprint and observability counters.

SubstrateSection

One compile-time typed slot per substrate: chapter observations, reductions, book contributions, corpus aggregates and measured memos.

FindingSection

Per-rule, chapter-local resident finding partitions. Assembly rebases them once to the current global corpus.

SharedTokens

Transition-local, layout-shaped and content-stamped. Built once per requested chapter, read sequentially by six drives, then dropped.

Disposable by contract
Dropping a cache or missing a stamp may cost a cold rebuild. It cannot change output. No caller-owned provenance or “changed” hint participates in correctness.
08
Execution order

Why cold walks more than warm

Substrate independence describes ownership and validity. Today’s scheduler also drives them independently, one substrate at a time.

Current · substrate outer

Each active substrate plans its dirty chapters

for substrate in active: dirty = plan(substrate) map(dirty chapters) reduce → judge → materialize

Cold cache: most chapters are dirty for every active substrate, so the corpus is rescanned several times. Warm edit: each drive usually maps only the changed chapter and reuses the rest.

Shared mechanical work

Tokens are already hoisted within one analyze

first token consumer: build ChapterTokens slot later five consumers: decode same slot after transition: drop slots

This removes duplicate tokenization without coupling substrate stamps, reduction or judging. Tape/grapheme sharing needs a different execution order or a compact codec.

Parallel shape
Native mapping may fan out independent books or sufficiently large chapter work under Rayon. Reduction within a book stays ordered. The shipped wasm build is serial.
Candidate, not scheduled
Chapter-outer selective map hoisting could build token/tape/grapheme views for a chapter and dispatch only the substrates dirty there. It preserves substrate ownership, but changes the central scheduler and has no demonstrated editor UX need yet.

10
Editor recipe

Persisted first, resident thereafter

Construct

Build Galley({ target, source, config }). Retain the exact immutable ordered keys[] snapshot.

Validate cache

Compare stored bytes with expected IDs; render accepted compact findings while analysis warms.

Mutate + debounce

Call chapter/book/config verbs as editor state changes. They update hashes and Dirty state, not findings.

Analyze + reconcile

Transfer the returned buffer worker→main and reconcile against the previous JS snapshot.

Two surfaces
Resident Galley supports lazy detailed args and incremental work. Stateless analyze_vref is a compact one-shot packed surface; consumers needing detailed messages use Galley.

Sharp edges

Small facts with large consequences

Keys must match bytes

Decode against the exact immutable ordered duplicate-preserving keys array used to mint the buffer.

Two offset units

Core Span is UTF-8 byte offsets. The packed wire is UTF-16 code units for direct JS/editor use.

Index is not identity

key_idx may rebase after insertion. Public JS identity uses resolved sid, duplicate ordinal, code and span.

Wasm memory is high-water

Linear memory does not shrink, though the allocator reuses freed regions. Avoid multiplying resident Galleys blindly.

Reference is narrow

Only prop.length-ratio declares target+reference input; it emits nothing when reference is absent.

One semantic engine

One-shot and resident calls use the same core transition. The cache changes cost, not behavior.
